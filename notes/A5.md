# A5 — La fiche d'une ville

| Adresse | Code HTTP | Qui a répondu / message |
|---|---|---|
| /villes/1 | 200 | la fiche de Calais |
| /villes/5 | 200 | la fiche de Lille |
| /villes/999 | 404 | l'EntityValueResolver de Doctrine : `"App\Entity\Ville" object not found by "Symfony\Bridge\Doctrine\ArgumentResolver\EntityValueResolver".` |
| /villes/abc | 404 | le routeur : `No route found for "GET http://localhost:8080/villes/abc"` |
| /villes/0 | 404 | l'EntityValueResolver, même message que /villes/999 |

- `/villes/abc` : même message que `/villes/999` ? Pourquoi ?
  > Non. `abc` ne respecte pas `requirements: ['id' => '\d+']`, donc AUCUNE route ne
  > correspond : c'est le routeur qui répond 404, le contrôleur n'est jamais appelé.
  > Pour 999 (et 0), la route correspond, mais le `find()` automatique ne trouve rien en base.
- Combien de vérifications écrites à la main ici (contre trois en séance 3) ?
  > Zéro : le format de l'id est vérifié par le `requirements` de la route, et l'existence
  > de la ville par le résolveur `Ville $ville`.
