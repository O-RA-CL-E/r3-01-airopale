# A2 — L'entité Ville

- Que vaut `length` pour `nom` ?
  > 100 : `#[ORM\Column(length: 100)]`, d'où un `VARCHAR(100)` en base.
- Pourquoi `$id` n'a pas de setter ?
  > L'id est généré par la base (`#[ORM\GeneratedValue]`, AUTO_INCREMENT) : c'est Doctrine qui
  > le remplit après l'INSERT. Le code ne doit jamais le choisir ni le modifier, sinon on
  > pourrait changer l'identité d'un objet ou créer des doublons.
- `setNom()` renvoie `static` : qu'est-ce que ça permet d'écrire ?
  > Des appels chaînés (interface fluide) :
  > `$ville->setNom('Calais')->setLatitude(50.95)->setLongitude(1.85);`
- D'où viennent `find()`, `findAll()`, `findBy()` dans `VilleRepository` ?
  > Par héritage : `VilleRepository` étend `ServiceEntityRepository`, qui étend
  > `EntityRepository` de Doctrine. C'est elle qui définit find, findAll, findBy, findOneBy, count.

## La migration
- `CREATE TABLE` produit par `up()` :
```sql
CREATE TABLE ville (id INT AUTO_INCREMENT NOT NULL, nom VARCHAR(100) NOT NULL, latitude DOUBLE PRECISION NOT NULL, longitude DOUBLE PRECISION NOT NULL, PRIMARY KEY (id)) DEFAULT CHARACTER SET utf8mb4
```
- Type MySQL choisi pour un `float` PHP :
  > `DOUBLE PRECISION` (affiché `double` dans Adminer) : un flottant sur 8 octets.
- Que fait `down()` ?
  > L'inverse de `up()` : `DROP TABLE ville`. Elle sert à annuler la migration
  > (`doctrine:migrations:migrate prev`).
